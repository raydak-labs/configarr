# Prowlarr v3 plan

[Research](../research/2026-11-03-prowlarr-v3-compatibility.md)

Status: container matrix added on `feat/prowlarr-v3`. No sync change.

## Do now

Same shape as Sonarr v5 / Radarr v7: a second container, digest pin, and a rerun of the existing feature file. The client stays on `/api/v1`.

- e2e service `prowlarr-v3` on `19697`, image `develop-3.0.0.5737-ls280`.
- `examples/full` service on `6508`. Sample YAML still targets 2.7 only.
- `pnpm test:e2e:arr:prowlarr-v3` overrides `PROWLARR_BASE_URL` and is part of `pnpm test:e2e:arr`.
- CI waits `/api/v1/system/status` on `19697`.
- Renovate develop-tag regex includes `lscr.io/linuxserver/prowlarr`. Stable `2.7.0` stays on normal docker versioning.

Application fixtures still store `prowlarrUrl: http://prowlarr:9696`. That is a saved field, and `sync_indexers` is false, so the v3 rerun does not need the v3 hostname. Change it only if a live run rejects the value.

## Do not do

- No second generated client, no version branch in `ProwlarrClient`, no YAML migration.
- Do not retarget `generate-api.ts`. It already tracks floating `develop`, which is ahead of this pin (`3.0.1`). Leave it until a v3 commit actually changes a resource Configarr maps.
- Do not duplicate the full example's `prowlarr:` block onto v3. Nothing in the schema differs.

## Later, only if upstream grows

No GitHub issue yet. Open one when a merged change adds a resource or field Configarr should write. The only candidate seen is unmerged Gamarr applications ([Prowlarr #2725](https://github.com/Prowlarr/Prowlarr/pull/2725)).

`allowedHosts` and `trustedNetworks` are already on 2.x host config. They are a host-config feature, not v3 support.

## Remove once v3 is stable

Once a stable v3 image replaces 2.7 and the existing suite passes against it, delete the extra stack. Bump the `prowlarr` service image, drop `prowlarr-v3` (e2e port `19697`, examples port `6508`), `test:e2e:arr:prowlarr-v3`, the CI wait, and the develop-tag Renovate exception if the pin is a normal version tag again. That follow-up is a `chore:` (no release note). No sync code to undo.

## Verify

`pnpm test:e2e:arr:prowlarr-v3` against the new container, including the idempotent second run already in `prowlarr.e2e.test.ts`. Unit tests do not cover this image.
